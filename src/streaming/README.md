# Smart Meter Streaming

This folder contains the **Spark Structured Streaming** job that converts raw smart-meter events from Kafka into useful real-time grid metrics.

## 1. What this stream does

`smart_meter_stream.py` performs this flow:

```text
Kafka smart-meter events
        ↓
Parse JSON
        ↓
Validate readings
        ↓
Convert event timestamp
        ↓
Calculate grid import
        ↓
Group readings into 5-minute windows
        ↓
Aggregate by grid zone
        ↓
Calculate renewable contribution
        ↓
Write zone metrics to PostgreSQL
```

The purpose is to answer:

> **What is the electricity demand, solar contribution, and grid dependency of each zone during each time window?**

---

## 2. Input data

Spark reads from the Kafka topic:

```text
smart-meter-readings
```

Kafka broker inside Docker:

```text
kafka:29092
```

Each smart-meter event contains:

```text
event_id
schema_version
meter_id
household_id
power_consumption_kwh
solar_generation_kwh
grid_zone
timestamp
```

Spark also keeps Kafka metadata:

```text
kafka_key
partition
offset
```

### Why keep Kafka metadata?

These values help later with:

- debugging failed events,
- tracing where an event came from,
- monitoring Kafka consumption,
- investigating duplicate or missing records.

---

## 3. Event validation

Before calculating metrics, invalid readings are removed.

A reading must contain valid values for:

```text
event_id
meter_id
household_id
grid_zone
event_timestamp
```

and:

```text
power_consumption_kwh >= 0
solar_generation_kwh >= 0
```

### Purpose

This prevents incorrect values such as negative electricity consumption from affecting the final grid metrics.

---

# 4. Calculations

## 4.1 Grid import

### Purpose

`grid_import_kwh` shows how much electricity must be supplied by the main grid after using available solar generation.

### Calculation

```text
grid_import_kwh =
    max(
        power_consumption_kwh - solar_generation_kwh,
        0
    )
```

### Example 1

```text
Consumption = 0.50 kWh
Solar       = 0.20 kWh

Grid Import = 0.50 - 0.20
            = 0.30 kWh
```

### Example 2

```text
Consumption = 0.30 kWh
Solar       = 0.45 kWh

Grid Import = 0 kWh
```

### Assumption

If solar generation is higher than consumption, the extra solar energy is currently ignored.

The simulator does **not yet calculate solar export back to the grid**.

---

## 4.2 Total zone consumption

### Purpose

Shows the total electricity demand of a grid zone during one 5-minute window.

### Calculation

```text
total_consumption_kwh =
    sum(power_consumption_kwh)
```

### Example

If three households in `ZONE-A` use:

```text
HH-001 = 0.40 kWh
HH-004 = 0.35 kWh
HH-007 = 0.50 kWh
```

then:

```text
total_consumption_kwh
= 0.40 + 0.35 + 0.50
= 1.25 kWh
```

---

## 4.3 Total solar generation

### Purpose

Shows how much electricity is generated by household solar panels in a grid zone during the window.

### Calculation

```text
total_solar_generation_kwh =
    sum(solar_generation_kwh)
```

### Example

```text
HH-001 solar = 0.20 kWh
HH-004 solar = 0.10 kWh
HH-007 solar = 0.00 kWh
```

then:

```text
total_solar_generation_kwh
= 0.20 + 0.10 + 0.00
= 0.30 kWh
```

---

## 4.4 Total grid import

### Purpose

Shows how much electricity the complete zone still needs from the main grid after household solar generation is used.

### Calculation

First, grid import is calculated for each household:

```text
household_grid_import =
    max(consumption - solar, 0)
```

Then Spark adds all household values:

```text
total_grid_import_kwh =
    sum(household_grid_import)
```

### Example

```text
Household 1 grid import = 0.20 kWh
Household 2 grid import = 0.30 kWh
Household 3 grid import = 0.40 kWh
```

then:

```text
total_grid_import_kwh
= 0.20 + 0.30 + 0.40
= 0.90 kWh
```

---

## 4.5 Renewable contribution

### Purpose

Shows what percentage of the zone's electricity consumption is covered by solar generation.

This helps measure how dependent the zone is on renewable energy.

### Calculation

```text
renewable_contribution_pct =
    (
        total_solar_generation_kwh
        / total_consumption_kwh
    )
    × 100
```

### Example

```text
Total Consumption = 10 kWh
Solar Generation  = 3 kWh
```

then:

```text
Renewable Contribution
= (3 / 10) × 100
= 30%
```

### Assumption

The value can be greater than `100%` if simulated solar generation is higher than consumption.

That would mean the zone produced more solar energy than it consumed.

Excess export is not separately calculated yet.

---

## 4.6 Meter readings

### Purpose

`meter_readings` shows how many smart-meter events were included in the zone and time window.

### Calculation

```text
meter_readings =
    count(household_id)
```

Example:

```text
ZONE-A
10:00-10:05

7 smart-meter events received
```

then:

```text
meter_readings = 7
```

### Important note

This is currently the **number of readings**, not the number of unique households.

---

# 5. Event-time windowing

The stream groups readings into:

```text
5-minute simulated-time windows
```

Example:

```text
10:00-10:05
10:05-10:10
10:10-10:15
```

## Purpose

Instead of showing every single household reading separately, Spark combines many readings into useful zone-level summaries.

Example:

```text
20 raw household readings
        ↓
Grouped by time + zone
        ↓
ZONE-A summary
ZONE-B summary
ZONE-C summary
```

The window uses the event's simulated timestamp, not the time Spark receives the message.

---

# 6. Watermark

The stream uses:

```text
10-minute watermark
```

## Purpose

Some events may arrive late.

Example:

```text
Event time   = 10:02
Arrival time = 10:08
```

Spark can still include the event in the correct window.

The watermark also helps Spark remove very old streaming state from memory.

---

# 7. Simulated time

The producer uses:

```text
5 real minutes = 1 simulated day
```

Therefore:

```text
1 real second ≈ 4.8 simulated minutes
```

A 5-minute simulated window is useful because approximately one batch of generated readings falls into each time window.

---

# 8. Final zone metrics

For every:

```text
5-minute window
+
grid_zone
```

Spark produces:

```text
window_start
window_end
grid_zone
total_consumption_kwh
total_solar_generation_kwh
total_grid_import_kwh
renewable_contribution_pct
meter_readings
```

Example:

```text
Window: 12:00-12:05
Zone: ZONE-A

Total Consumption       = 2.80 kWh
Solar Generation        = 1.10 kWh
Grid Import             = 1.70 kWh
Renewable Contribution  = 39.29%
Meter Readings          = 7
```

---

# 9. Main assumptions

- The input data is simulated.
- Negative consumption and solar values are invalid.
- Grid import cannot be negative.
- Excess solar export is not modelled yet.
- Metrics are grouped by grid zone.
- A 5-minute simulated-time window is used.
- A 10-minute watermark is used for late events.
- `meter_readings` counts events, not unique households.
- Finalized zone and daily household summaries are stored in PostgreSQL.

---
